# tap-to-fix Dashboards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The two pages people actually look at: a reviewer's private list of pages to review (`/r/`), and Ben's owner dashboard (`/o/`) for reviewers, sites, assignments and the command that starts a review cycle.

**Architecture:** Two static pages built by plan 2's esbuild script (`service/client/dash/reviewer.ts`, `owner.ts`) into `service/public/r/index.html` and `service/public/o/index.html` plus their JS. They call plan 1's API with a Bearer token taken from the URL hash (`#ttf=` / `#owner=`), which browsers never send to a server or in a Referer. Rendering is plain DOM code split into pure view functions (data in, HTML string out, tested with Vitest) and a thin wiring layer (tested with Playwright).

**Tech Stack:** TypeScript, esbuild, Vitest + happy-dom, @playwright/test 1.61.1 (harness from plan 2).

**Spec:** `docs/superpowers/specs/2026-11-20-tap-to-fix-design.md` · plan 1 notes `2026-11-20-01-service-core-followups.md` · plan 2 `2026-11-20-02-comment-layer.md` (+ its followups once written).

## Global Constraints

- Everything in plan 2's Global Constraints applies (American English, Paper tokens from `client/paper.ts`, 17 px body minimum, ≥ 44 px tap targets, monochrome SVG icons, no emoji, explicit `git add` paths, foreground tests).
- **Fewer cards:** open lists with dividers and ruled tables, no boxed cards; the one highlighted box is the owner's "ready for a review cycle" box.
- Every response from the service carries `Referrer-Policy: no-referrer`; nothing logs query strings or hashes.
- Tokens: reviewer page reads `#ttf=TOKEN`, owner page reads `#owner=TOKEN`. Each is copied to `localStorage` (`ttf:dash-token`, `ttf:owner-token`) and used when the hash is missing. **The hash is left in the address bar** on the reviewer page so "Add to Home Screen" saves a working link. All storage access in try/catch.
- Reviewer links are always `<service origin>/r/#ttf=<token>`.
- Reviewer-facing wording: chips "Updated since you looked", "New", "All done"; status labels as in plan 2.
- Fix command shown to the owner: `/tap-to-fix:fix <reviewer first name, lowercased> <site slug>`, e.g. `/tap-to-fix:fix alexis bonus-decade`. (Plan 4's skill matches the reviewer name case-insensitively by first word; record this in the followups.)
- Designed at 390 px first, then 1280 and 1440. Run `/proofs:visual-qa` at 1440, 1280 and 390 before calling the plan done.

## Review Focus

1. A revoked or wrong token on either page → a plain sentence ("This link no longer works. Ask for a new one." / owner: the token form again), never a blank page or a JSON error → Tasks 2, 3 tests.
2. Long page titles and paths at 390 px → wrap, never overflow horizontally (no horizontal page scroll) → Task 4 Playwright check of `scrollWidth <= innerWidth`.
3. Reviewer with zero assignments / owner with zero reviewers or sites → friendly empty state that says what to do next → Tasks 2, 3 view tests.
4. Owner revokes or reissues a link by mistake → confirm step naming the reviewer and saying the old link stops working → Task 3 test.
5. Owner removes an assignment that has comments → confirm says how many comments go with it → Task 3 test.

### Task 2: Reviewer dashboard

**Files:**
- Create: `service/client/dash/reviewer.ts`
- Test: `service/test/client/dash-reviewer.test.ts`, `service/e2e/dashboards.spec.ts` (reviewer part)

**Interfaces:**
- Consumes: `GET /api/me` → `{ name, assignments: [{ id, site:{slug,name,origin}, path, title, url, status, progress, counts:{total,settled,in_progress,open}, is_new, is_updated }] }`; `POST /api/me/assignments/:id/opened`.
- Produces: `renderReviewer(data: MeResponse): string`, `chipFor(a): "Updated since you looked" | "New" | "All done" | null` (precedence: updated, then new, then all done when `counts.total > 0 && counts.settled === counts.total`), `countLine(a): string`, `mountReviewer(win: Window): Promise<void>`.

Layout (Paper variant A + progress circle from variant B): greeting "Hi Alexis." in the serif at 30 px; one sentence in `--mut`: "Tap a page to open it, then tap anything on it that should change."; then an open list with 1 px `--line` dividers. Each row is one `<a>` (min height 72 px): progress ring left; title (serif 20 px); "Site name · /path" in `--mut` 17 px; count line ("No comments yet", "3 comments · 1 being fixed · 2 settled"); chip on the right (accent-soft for Updated/New, plain for All done). When the reviewer has pages on more than one site, group rows under a site heading. Empty: "Nothing to review yet. Ben will add pages here." 401: "This link no longer works. Ask for a new one." Network error: "Can't reach the review service right now." with a "Try again" button.

Row tap: `fetch(opened, { method: "POST", keepalive: true })` without awaiting longer than 1.5 s, then `location.href = a.url`.

### Task 3: Owner dashboard

**Files:**
- Create: `service/client/dash/owner.ts`
- Test: `service/test/client/dash-owner.test.ts`, `service/e2e/dashboards.spec.ts` (owner part)

**Interfaces:**
- Consumes: `GET /api/owner/overview` (`{ reviewers:[{id,name,revoked,unsettled_count,ready_count}], assignments:[{id,site,path,title,reviewer:{id,name},status,counts:{open,in_progress,settled},pr_urls}] }`), `GET /api/owner/sites`, `POST /api/owner/sites|reviewers|assignments`, `POST /api/owner/reviewers/:id/reissue|revoke`, `DELETE /api/owner/assignments/:id`.
- Produces: `readyBatches(overview): { reviewerName: string; siteSlug: string; siteName: string; open: number; command: string }[]` (one per reviewer+site with open > 0, most open first); `fixCommand(reviewerName, siteSlug): string`; `reviewerLink(origin, token): string`; `renderOwner(state: OwnerState): string` where `OwnerState = { sites, overview, selectedReviewerId: string | null, flash: { kind: "link"; name: string; url: string } | null }`; `mountOwner(win): Promise<void>`.

Layout (Paper variant A). No token → a small form "Paste your owner token" (password input + "Open") that sets `#owner=` and reloads. Desktop (≥ 900 px): reviewers column on the left (name, "N open", "Link off" for revoked; selected one highlighted; "+ Add a reviewer" inline form → on success a flash block "Text this link to Alexis" with the link and a Copy button); main column: the ready box(es) in `--soft` ("Alexis has 7 comments ready for a review cycle on Bonus Decade", the command in a monospace line, Copy button); "+ Assign a page" inline form (site select, reviewer select, path, title); ruled table of assignments (Page: title + path; Reviewer; Status chip — not_started "Not started", open "Open", in_progress "In progress", done "Done"; Page link → `origin + path` new tab; PR link(s) "PR #123" parsed from the URL, else "PR"; a remove control). Selecting a reviewer filters the table and shows "New link" and "Turn off link" for them. Sites section at the bottom: list of sites (name, origin, repo, slug) and "+ Add a site" (slug, name, origin, repo). Phone (390 px): one column in the order ready box, reviewers, assign, table rendered as stacked rows (title, path, reviewer · status, links).

Confirm steps (use `confirm()`; copy is the contract): reissue — "Make a new link for Alexis? Alexis's old link stops working."; revoke — "Turn off Alexis's link? Alexis won't be able to review until you make a new one."; remove assignment — "Remove “Digital Detox” from Alexis's list? Its 3 comments are deleted too." (omit the second sentence when 0 comments). No pronouns for reviewers: repeat the name. API errors show the service's `error` message in a `--warn` line next to the form that failed.
