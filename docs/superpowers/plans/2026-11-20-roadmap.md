# tap-to-fix — build roadmap

Spec: `docs/superpowers/specs/2026-11-20-tap-to-fix-design.md`

The spec covers six subsystems. Each gets its own plan, written when the one before it ships, so each plan can lean on real interfaces rather than guessed ones. Each produces working, tested software on its own.

| # | Plan | Delivers | Depends on |
|---|---|---|---|
| 1 | **Service core** (`2026-11-20-01-service-core.md`) | Cloudflare Worker + D1 + R2: sites, reviewers and their private links, assignments, comments with screenshots, statuses, the batch and status API Claude uses. Tested locally; not yet deployed. | — |
| 2 | Comment layer | The script tag: loader that wakes only with a reviewer token, Shadow-DOM overlay, tap-to-pin, Paper bottom sheet, in-browser screenshot + element location, saved via plan 1's API. Playwright tests on a fixture page at 390 px. | 1 |
| 3 | Dashboards | Reviewer dashboard (Paper A + progress circle) and owner dashboard (Paper A), served by the Worker. Visual QA at 1440 / 1280 / 390. | 1 |
| 4 | Claude Code plugin | `.claude-plugin`, setup skill (deploys to Ben's Cloudflare account with new D1 + R2, prints script tag and owner link), `/tap-to-fix:fix <reviewer> <site>` wrapping `proofs:review-cycle`, status command, batch-file fallback. | 1 (2, 3 for a full run) |
| 5 | Bonus Decade hookup | In `longevity-tracker`: script tag on public layouts, CSP additions (`script_src`, `connect_src`, `img_src`). Follows that repo's worktree/PR rules; Ben deploys. | 2, 4 |
| 6 | Website + open-source release | GitHub repo public, README, site on GitHub Pages like Proofs. | all, after Ben has used it |
